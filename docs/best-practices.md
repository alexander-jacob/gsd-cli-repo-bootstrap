# Best practices

## Keep project intent reviewable

Commit the complete policy and persistent default together when a change needs
both. Keep effective config, synchronization state, credentials and logs out of
Git. Review changes generated by `init`, especially migration of a previously
tracked working config.

Use separate worktrees for concurrent sessions with different presets. The
configuration lock protects preparation, not the entire AI session.

## Match effort to the task

Start with medium for routine execution and use high for demanding planning or
verification. Measure results before changing the whole project. Prefer named
agent pins when only one job needs a different level.

Changing session effort does not change every agent or reviewer. Check all three
controls. Claude installed effort frontmatter needs separate attention; the
launcher never silently updates global agent definitions.

## Preview before launching

Run `check` and `--config` after changing policy or updating GSD. Use `--details`
to investigate mismatches. A zero preview exit code means the inspection
completed, not that every setting matched. Inspect session logs after important
runs to compare intent with available execution evidence.

## Select reviewers deliberately

Choose the group for the plan being reviewed rather than assuming the selected
runtime identifies its author. Keep reviewers independent of the launch level.
Enable DeepSeek or parallel reviews only when they serve the task; OpenRouter
reviewers incur usage charges. Gemini Carbon can spend more reasoning tokens
than Argon, so assess review value as well as model capability.

## Choose permission behavior explicitly

Use `--secure` when you want normal CLI permission settings. Remember that the
shipped execution presets and Codex planning bypass prompts by default. Check
forwarded arguments, because they may override models, effort or permissions.

```sh
gsd-cli exec codex medium --secure -- --resume
```

The first `--` starts child arguments. Put launcher inspection flags before it.
Run from the destination project; forwarded Codex directory switches are rejected.

## Upgrade without losing local decisions

Update the package and the selected GSD installations, then rerun checks. Existing
project policies retain their chosen models. Compare your policy with the starter
example and adopt model changes deliberately. Do not replace the entire policy
just to update one reviewer.

If synchronization reports a conflict, reconcile the named path. If recovery is
pending, retain the journal and edited files until you understand the interrupted
transaction. Consult the [launcher reference](LAUNCHER.md#automatic-capture-and-recovery).
